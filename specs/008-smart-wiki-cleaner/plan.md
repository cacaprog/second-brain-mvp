# Implementation Plan: Smart Wiki Cleaner — Content-Aware Consolidation

**Branch**: `008-smart-wiki-cleaner` | **Date**: 2026-04-25 | **Spec**: [spec.md](spec.md)  
**Input**: Feature specification from `/specs/008-smart-wiki-cleaner/spec.md`

## Summary

`wiki_cleaner.py` currently triggers LLM consolidation for every wiki page with 3+ paragraphs, regardless of content. This plan adds two guards before the LLM call: (1) skip article/paper pages entirely by querying SQLite for `note_type`, and (2) skip pages whose paragraphs are all unique (no repetition). Only pages with proven duplicate paragraphs that reduce above a 2-paragraph threshold reach the LLM.

## Phase 0: Research

### Decision Log

**D1: How to detect article pages**

Three candidates:
- A. Query SQLite: `db.get_notes_by_wiki_page(slug)` to get note IDs, then check `note_type` on each.
- B. Structural heuristic: check if body contains `## Summary` + `## Key Findings` (or `## Key Arguments`).
- C. Check if source path contains `/articles/` or `/papers/`.

**Decision: A (SQLite query)**  
Rationale: Authoritative source. B and C would break if the user edits the page or moves source files. The DB already has `get_notes_by_wiki_page()` from T004 in feature 007. Zero new code in `db.py` needed.

Edge case: orphaned pages (no DB rows) → treat as non-article (fail-open, safe direction).

**D2: How to extract slug from a wiki page path**

`_parse_front_matter()` already returns the full front matter dict. The `slug` key is always present (enforced by `write_wiki_page`). Use `front_matter["slug"]` and `front_matter["domain"]`.

**D3: Paragraph deduplication algorithm**

Exact string match (strip + lowercase), identical to `wiki_merger.py`'s `_consolidate_bodies()`. No fuzzy matching — out of scope.

**D4: Three-tier decision tree for `_process_page()`**

```
1. Extract paragraphs
   └── len(paragraphs) <= 2  →  return "skipped"         (existing fast path)
2. Query DB for note_type
   └── any note_type == "article"  →  return "skipped_article"
3. Deduplicate paragraphs (exact match)
   ├── unique_count == original_count  →  return "skipped_no_rep"
   ├── unique_count <= 2  →  write back unique paragraphs, return "deduped"
   └── unique_count > 2   →  call LLM, return "consolidated"
```

**D5: Summary counter changes**

Current counters: `scanned`, `changed`, `skipped`, `errored`.  
New counters: `scanned`, `consolidated`, `deduped`, `skipped_short`, `skipped_article`, `skipped_no_rep`, `errored`.

`changed` is split into `consolidated` (LLM used) and `deduped` (direct write, no LLM) for clarity.

**D6: DB access in wiki_cleaner.py**

`wiki_cleaner.py` does not currently import `db.py`. Add `from db import get_db` and call it once at startup (or lazily). The DB path comes from `cfg` (same settings.yaml the cleaner already loads).

### `_deduplicate_paragraphs()` helper

```python
def _deduplicate_paragraphs(paragraphs: list[str]) -> list[str]:
    seen: set[str] = set()
    unique: list[str] = []
    for p in paragraphs:
        key = p.strip().lower()
        if key not in seen:
            seen.add(key)
            unique.append(p)
    return unique
```
